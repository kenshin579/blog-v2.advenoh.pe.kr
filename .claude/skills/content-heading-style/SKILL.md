# Content Heading Style

`contents/**/index.md` 파일의 Heading 번호 체계를 일관되게 유지하는 Skill이다.

## Heading 번호 규칙

모든 Heading에는 계층적 번호를 부여한다:

- **H1**: `# N. 제목` (예: `# 1. 들어가며`)
- **H2**: `## N.M 제목` (예: `## 1.1 Topic 구조`)
- **H3**: `### N.M.K 제목` (예: `### 1.1.1 계층적 네이밍`)

번호는 각 레벨별로 1부터 시작하며, 상위 Heading이 바뀌면 하위 번호는 1로 초기화된다.

## H3 깊이 적용 가이드

H3(`### N.M.K`) 같은 깊은 3단계 번호는 **해당 섹션의 내용이 충분히 길어 세분화가 필요할 때만** 적용한다.

- 내용이 짧은 소제목까지 굳이 `N.M.K`로 잘게 번호 매기지 않는다. 과도한 세분화는 오히려 가독성을 해친다.
- 섹션이 여러 문단·코드 블록·예제로 길어 하위 구분이 의미 있는 경우에 H3 번호를 사용한다.
- 짧은 항목이라면 H2(`## N.M`)까지만 쓰거나, 번호 없는 본문/리스트로 풀어내는 편이 낫다.

이는 강제 규칙이 아니라 판단 가이드다. 이미 H3로 작성된 기존 Heading의 번호 형식을 교정하는 것은 그대로 수행하되, **새로 Heading을 추가할 때** 깊이를 결정하는 기준으로 적용한다.

## 동작 방식

`contents/` 디렉토리의 index.md 파일을 작성하거나 수정할 때 다음을 수행한다:

### 1. 새 글 작성 시

Heading을 작성할 때 반드시 아래 번호 체계를 적용한다:

```markdown
# 1. 들어가며
# 2. 개발 환경
# 3. 주제 제목
## 3.1 소제목 A
### 3.1.1 세부 항목
### 3.1.2 세부 항목
## 3.2 소제목 B
# 4. 마무리
# 5. 참고
```

### 2. 기존 글 수정 시

Heading을 추가/삭제/이동한 후 전체 번호를 재정렬한다.

**변환 대상 패턴:**

| 잘못된 패턴 | 올바른 패턴 |
|------------|-----------|
| `# 제목` (번호 없음) | `# N. 제목` |
| `# X장. 제목` | `# N. 제목` |
| `## 제목` (번호 없음) | `## N.M 제목` |
| `### 제목` (번호 없음) | `### N.M.K 제목` |
| `# 1.제목` (공백 없음) | `# 1. 제목` |

### 3. 검증

수정 완료 후 아래 조건을 확인한다:

- 모든 H1이 `# 숫자. 제목` 형식인지
- 모든 H2가 `## 숫자.숫자 제목` 형식인지
- 모든 H3이 `### 숫자.숫자.숫자 제목` 형식인지
- 번호가 순차적으로 증가하는지
- 상위 Heading이 바뀔 때 하위 번호가 1로 초기화되는지

## 적용 제외 대상 (파일/디렉토리)

다음 콘텐츠는 튜토리얼 글이 아니라 번호 체계가 맞지 않으므로 **이 Skill을 적용하지 않는다**:

- **`contents/biweekly/**`**: 격주 뉴스 다이제스트. H1 없이 이모지 H2 섹션(`## ☁️ Cloud & Infra` 등)으로 구성되며 번호를 부여하지 않는다.
- **`contents/**/qa-*/index.md`**: Q&A 레퍼런스 목록. 상태 그룹 헤더(`## <span style="color:...">[답변완료]</span>`)와 질문 헤더 구조라 계층 번호를 매기면 의미가 깨진다.

위 경로의 파일은 Heading 번호 위반으로 보지 않으며 수정하지 않는다.
