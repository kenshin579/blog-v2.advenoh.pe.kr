# Blog 다국어 SEO (Plan 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 다국어 SEO를 완성한다 — 글 제목 중복 수정, ko↔en hreflang 상호 링크, sitemap에 영어 URL 포함(생성기 일원화), 언어별 RSS(`/rss.xml` ko, `/en/rss.xml` en).

**Architecture:** 메타데이터는 Next App Router `generateMetadata`로 페이지에서 생성. 루트 레이아웃의 title 템플릿(`%s | Frank's IT Blog`)과 페이지 title의 중복을 제거한다. hreflang은 ko/en 짝이 모두 존재할 때만 상호 `alternates.languages`로 emit. sitemap은 Next 네이티브 `app/sitemap.ts` 하나로 일원화하고(스크립트 기반 stale sitemap 제거), ko+en URL을 모두 포함. RSS는 `lang` 인자를 받는 생성기로 리팩터링해 ko/en 두 피드를 만든다.

**Tech Stack:** Next.js App Router(static export), TypeScript, xmlbuilder2(RSS), tsx 스크립트. 테스트 러너 없음 → 검증은 `npm run check`, `npm run build`(out/ 산출물 확인), 생성된 xml grep.

**Plan 1·2에서 이어짐:** manifest 항목에 `lang` 필드 존재. `lib/articles.ts` 함수는 `lang` 인자 지원. `lib/i18n/lang.ts`의 `localizeHref` 존재. `/en` 라우트 전체 존재.

## Task 1: 글 제목 중복(`| Frank's IT Blog` ×2) 수정

**Files:**
- Modify: `app/[slug]/page.tsx`
- Modify: `app/en/[slug]/page.tsx`

루트 레이아웃 `app/layout.tsx`의 metadata는 `title.template = "%s | Frank's IT Blog"`. 따라서 페이지가 문자열 title을 반환하면 자동으로 suffix가 붙는다. 현재 `app/[slug]/page.tsx`는 `title: \`${article.frontmatter.title} | Frank's IT Blog\`` 를 반환해 결과가 `... | Frank's IT Blog | Frank's IT Blog`로 중복된다.

- [ ] **Step 1: 한국어 글 페이지 title 수정**

`app/[slug]/page.tsx`의 `generateMetadata` 반환에서 `title`을 프론트매터 제목만 반환하도록 변경(템플릿이 suffix 추가):
```ts
    title: article.frontmatter.title,
```
(OpenGraph 등 다른 곳의 title은 그대로 둔다 — OG title은 템플릿 영향을 받지 않으므로 중복 아님.)

- [ ] **Step 2: 영어 글 페이지 title 수정**

`app/en/[slug]/page.tsx`도 동일하게 `title: article.frontmatter.title,`로 변경.

- [ ] **Step 3: 빌드 후 title 확인**

Run: `npm run generate:manifest && npm run build`
검증: `grep -o "<title>[^<]*</title>" "out/en/ksqldb-소개/index.html"`
Expected: `<title>Introducing ksqlDB | Frank's IT Blog</title>` (중복 없음). 한국어 글도 동일하게 단일 suffix.

- [ ] **Step 4: 커밋**

```bash
git add "app/[slug]/page.tsx" "app/en/[slug]/page.tsx"
git commit -m "fix: 글 제목 중복(| Frank's IT Blog ×2) 제거"
```

## Task 2: hreflang 상호 링크 (ko ↔ en)

**Files:**
- Modify: `lib/articles.ts` (헬퍼 추가)
- Modify: `app/[slug]/page.tsx`, `app/en/[slug]/page.tsx`

- [ ] **Step 1: 짝 존재 여부 헬퍼 추가**

`lib/articles.ts`에 추가(manifest 기반, 같은 slug의 다른 언어 변형 존재 여부):
```ts
export async function hasArticleVariant(slug: string, lang: 'ko' | 'en'): Promise<boolean> {
  const manifest = await loadManifest();
  return manifest.articles.some(a => a.slug === slug && a.lang === lang);
}
```

- [ ] **Step 2: 한국어 글에 hreflang 추가**

`app/[slug]/page.tsx`의 `generateMetadata`에서 현재 글 slug(`manifestArticle.slug`)와 title-slug를 구해, en 변형이 있으면 alternates에 양쪽을 emit. (titleSlug는 `getArticleTitleFromSlug(slug)`)
```ts
  const titleSlug = getArticleTitleFromSlug(manifestArticle.slug);
  const hasEn = await hasArticleVariant(manifestArticle.slug, 'en');
  const languages: Record<string, string> = { ko: `/${titleSlug}/` };
  if (hasEn) languages.en = `/en/${titleSlug}/`;
  // 반환 객체에 추가:
  //   alternates: { canonical: `/${titleSlug}/`, languages },
```
`generateMetadata` 반환 객체에 `alternates: { canonical: \`/${titleSlug}/\`, languages }` 추가. (기존 반환 필드 보존)

- [ ] **Step 3: 영어 글에 hreflang 추가**

`app/en/[slug]/page.tsx`에서 동일하게: ko는 항상 존재(영어는 한국어 원본에서 파생)하므로 `languages.ko = \`/${titleSlug}/\``, `languages.en = \`/en/${titleSlug}/\``, `canonical = \`/en/${titleSlug}/\``. (안전을 위해 `hasArticleVariant(slug,'ko')`도 확인해 없으면 ko 생략.)

- [ ] **Step 4: 빌드 후 hreflang 확인**

Run: `npm run build`
검증: `grep -o 'hreflang="[^"]*"' "out/en/ksqldb-소개/index.html"` 및 `grep -o 'hreflang="[^"]*"' "out/ksqldb-소개/index.html"`
Expected: 양쪽 모두 `ko`, `en` alternate 링크 포함.

- [ ] **Step 5: 커밋**

```bash
git add lib/articles.ts "app/[slug]/page.tsx" "app/en/[slug]/page.tsx"
git commit -m "feat: 글 ko↔en hreflang 상호 링크 추가"
```

```ts
  const koArticles = await getAllArticles('ko');
```

`scripts/generators/rss.ts`의 `generateRSS`에 `lang: 'ko' | 'en'`과 `selfHref`(atom:link href용) 파라미터를 추가. manifest에서 `recentArticles`를 `lang` 필터 후 상위 20개로 변경. 항목 URL은 lang에 따라 `${baseUrl}/...` 또는 `${baseUrl}/en/...`로 생성. `<channel><link>`와 `atom:link href`도 lang별로:
```ts
export async function generateRSS(
  manifestPath: string,
  outputPath: string,
  lang: 'ko' | 'en' = 'ko',
): Promise<void> {
  // ...
  const filtered = manifest.articles.filter(a => a.lang === lang);
  const recentArticles = filtered.slice(0, 20);
  const langPrefix = lang === 'en' ? '/en' : '';
  const channelLink = `${blogConfig.baseUrl}${langPrefix}`;
  const selfHref = `${blogConfig.baseUrl}${langPrefix}/rss.xml`;
  // channel link/atom:link self를 위 값으로
  // 각 item: const articleUrl = `${blogConfig.baseUrl}${langPrefix}/${article.slug.split('/').pop()}`;
  // 영어 피드는 channel language를 'en'으로
}
```
`<language>`는 `lang === 'en' ? 'en' : blogConfig.language`.

- [ ] **Step 2: readArticleContent가 영어 본문을 읽도록 lang 반영**

`readArticleContent(slug)`가 `index.md`만 읽는다면, en 피드에서는 `index_en.md`를 읽도록 `lang`을 전달. 함수 시그니처에 `lang` 추가하고 파일명 분기(`index_en.md` vs `index.md`). 호출부(item 생성 루프)에서 현재 `lang` 전달.

- [ ] **Step 3: generate-feeds.ts에서 ko/en 두 피드 생성**

```ts
  const rssKoOutput = path.join(process.cwd(), 'public', 'rss.xml');
  const rssEnDir = path.join(process.cwd(), 'public', 'en');
  const rssEnOutput = path.join(rssEnDir, 'rss.xml');
  if (!fs.existsSync(rssEnDir)) fs.mkdirSync(rssEnDir, { recursive: true });
  await generateRSS(manifestPath, rssKoOutput, 'ko');
  await generateRSS(manifestPath, rssEnOutput, 'en');
```
(`fs`, `path` import 확인. `public/en/rss.xml`은 빌드 시 `out/en/rss.xml`로 복사됨.)

Run: `npm run generate:manifest && npm run generate:feeds && npm run build`

- `ls out/en/rss.xml` — 존재
- `grep -c "<item>" public/en/rss.xml` — 1 (현재 영어 글 1건)
