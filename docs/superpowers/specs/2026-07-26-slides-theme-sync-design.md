# 슬라이드 테마를 블로그 테마와 동기화 설계

- 작성일: 2026-07-26
- 대상: `blog-v2.advenoh.pe.kr`
- 목표: 글에 임베드된 슬라이드와 새 탭으로 연 슬라이드가 블로그의 라이트/다크 설정을 따르게 한다
- 선행 작업: `2026-07-26-slides-embed-design.md` (슬라이드 임베드 기능)

## 배경 / 동기

슬라이드 임베드를 붙이고 나니 테마가 따로 논다. 블로그를 라이트 모드로 보고 있어도 글 안에 박힌 슬라이드는 자기 설정(또는 OS 설정)대로 어두운 채 남고, "새 탭에서 열기"로 열어도 마찬가지다. 한 페이지 안에서 배경색이 어긋나 보인다.

## 요구사항

- 블로그가 라이트면 임베드된 슬라이드도 라이트, 다크면 다크
- 블로그에서 테마를 토글하면 임베드가 **즉시** 따라 바뀐다 (새로고침 불필요)
- "슬라이드 새 탭에서 열기"로 연 페이지도 블로그와 같은 테마로 열린다
- 슬라이드 자체 테마 토글(`t` 키 / 테마 버튼)은 **남긴다** — 발표 중 조명에 맞춰 잠깐 바꾸는 용도. 단 그 변경은 그 화면에서만 유효하고, 다시 열면 블로그 기준으로 돌아온다
- 새 슬라이드를 만들 때 **추가로 기억해야 할 것이 없어야 한다**

## 현재 구조 (변경 전)

**블로그** — next-themes 0.4.6
- `app/layout.tsx:110-115`: `attribute="class"`, `defaultTheme="system"`, `enableSystem`
- `storageKey`를 덮어쓰지 않으므로 기본값 사용 → `localStorage["theme"]`에 `system` | `light` | `dark` 저장 (`node_modules/next-themes/dist/index.js`에서 `storageKey:o="theme"` 확인)
- `<html>`에 `class="dark"` 형태로 반영

**슬라이드** (`contents/{category}/{글폴더}/slides.html`)
- `<html data-theme="dark|light">` 속성으로 테마 표현
- CSS 3계층이 **이미 완비**되어 있다: `@media (prefers-color-scheme: dark)`(35행), `:root[data-theme="dark"]`(57행), `:root[data-theme="light"]`(77행). 라이트 모드를 새로 만들 필요가 없다
- `localStorage["deck-theme"]`에 자체 저장, 문서 하단 IIFE에서 읽어 속성 설정
- `toggleTheme()`(2184행)이 속성 변경 + `deck-theme` 저장 + **`drawHero()` 호출**. 표지 스파크라인을 테마 색으로 다시 그리는 것이라 테마 변경 시 반드시 함께 실행되어야 한다
- `t` 키와 `#btnTheme` 버튼이 `toggleTheme()`에 연결됨

**배포 경로**
- `scripts/copy-assets.ts`가 `slides.html` → `public/{글폴더}/slides/index.html`로 복사 (영문은 `public/en/...`)
- 즉 슬라이드는 블로그와 **같은 오리진**(`blog.advenoh.pe.kr`)에서 서빙된다

## 핵심 전제

**같은 오리진이므로 `localStorage`가 공유된다.** 슬라이드가 블로그의 `theme` 키를 그대로 읽을 수 있어 postMessage 같은 별도 통신 채널이 필요 없다. 이 하나로 임베드와 새 탭 두 요구사항이 동시에 해결된다.

덧붙여 `storage` 이벤트는 **값을 변경한 문서를 제외한** 같은 오리진의 모든 문서에 전달된다. 블로그 페이지가 테마를 바꾸면 그 안의 iframe 문서가 이벤트를 받으므로 실시간 동기화도 추가 배선 없이 얻는다.

## 설계

### 1. 동작 규칙

| 상황 | 동작 |
|---|---|
| 블로그 다크 → 글 열기 | 임베드도 다크 |
| 글에서 테마 토글 | 임베드가 즉시 따라 바뀜 (스파크라인 포함) |
| "새 탭에서 열기" | 블로그와 같은 테마로 열림 |
| 슬라이드에서 `t` 키 / 테마 버튼 | 그 화면에서만 반대 테마. 다시 열면 블로그 기준으로 복귀 |
| 블로그가 `system` + OS 다크 | 슬라이드도 다크 |

슬라이드 쪽 토글을 남기되 **블로그가 우선권을 갖는다**. "그 자리에서만 잠깐 바꾸기"는 되고, 영구 설정은 블로그 한 곳에서만 한다.

### 2. 주입 방식 — `scripts/copy-assets.ts`

동기화 스크립트를 슬라이드 원본에 직접 넣지 않고, **`public/`으로 복사하는 시점에 주입**한다.

검토한 대안:
- *슬라이드마다 스니펫 직접 작성* — 새 슬라이드마다 복붙해야 하고 로직 수정 시 전부 찾아 고쳐야 한다
- *공용 `.js` 파일을 `<script src>`로 참조* — 한 줄만 기억하면 되지만 슬라이드가 자기완결형이 아니게 된다

주입을 고른 이유:
- 새 슬라이드 제작 시 기억할 것이 늘지 않는다 (`transform-origin` 제약 하나로 충분하다)
- 기존 슬라이드에 소급 적용된다 — 다시 빌드하면 끝
- **원본 슬라이드는 여전히 완전한 자기완결형**이다. 로컬에서 파일을 직접 열어도 정상 동작하고, 배포본에만 기능이 얹힌다. 설계 문서에 적어둔 "외부 의존성 없는 자기완결형" 규약을 깨지 않는다
- 복사 단계를 이미 갖고 있어 자연스러운 자리다

**주입 지점: `</head>` 바로 앞.** 첫 페인트 전에 테마가 확정되어야 깜빡임이 없다. `</head>`가 없는 슬라이드는 주입을 건너뛰고 경고를 남긴다.

주입 블록 첫 줄에 출처 주석을 넣어 나중에 배포본을 열어본 사람이 혼란스럽지 않게 한다.

### 3. 주입되는 스크립트가 하는 일

1. **블로그 테마를 읽어 해석한다** — `localStorage["theme"]`가 없거나 `"system"`이면 `matchMedia('(prefers-color-scheme: dark)')`로 `light`/`dark` 중 하나로 확정한다.

2. **`<html data-theme>`에 즉시 반영한다.**

3. **`localStorage["deck-theme"]`에 같은 값을 써둔다.** 슬라이드 자체 초기화 코드가 문서 하단에서 `deck-theme`를 읽어 속성을 다시 설정하므로, 미리 같은 값으로 맞춰두면 둘이 싸우지 않는다. 동시에 "이전에 슬라이드에서 토글해둔 값"이 블로그 값으로 덮여 **새로 열면 블로그 기준**이라는 규칙이 자연히 성립한다.

4. **`storage` 이벤트를 구독한다.** `key === "theme"`이면 목표 테마를 다시 계산하고, 현재 `data-theme`와 다르면 **`#btnTheme`를 클릭한다.**

   속성을 직접 바꾸지 않고 버튼을 클릭하는 이유: 슬라이드의 `toggleTheme()`이 마지막에 `drawHero()`를 불러 표지 스파크라인을 다시 그리는데, 이 함수들이 모두 IIFE 안에 있어 바깥에서 호출할 수 없다. 버튼 클릭은 슬라이드 자신의 코드 경로를 그대로 타므로 스파크라인 갱신까지 따라온다.

   `#btnTheme`가 없는 슬라이드를 위해 **속성 직접 변경 폴백**을 둔다(이 경우 스파크라인은 다음 렌더까지 이전 색으로 남을 수 있다).

모든 `localStorage` 접근은 `try/catch`로 감싼다. 슬라이드 원본이 이미 그렇게 하고 있고, 프라이빗 모드 등에서 예외가 날 수 있다.

### 4. 복사 로직 변경

슬라이드는 내용이 바뀌므로 `fs.copyFileSync`를 쓸 수 없다. 읽어서 주입하고 쓰는 별도 경로가 필요하다.

- 이미지: 기존 `copyFiles()` 그대로
- 슬라이드: `readFileSync` → 주입 → `writeFileSync`

기존 mtime/size 스킵 로직은 슬라이드에 적용하지 않는다. 주입으로 크기가 달라져 어차피 매번 다시 쓰게 되고, 슬라이드는 글당 1~2개뿐이라 비용이 무시할 수준이다. (참고: 그 스킵 로직은 macOS 부동소수점 문제로 현재 이미지에서도 동작하지 않는다 — 별도 이슈)

### 5. 문서 갱신

- `CLAUDE.md` 슬라이드 섹션에 "배포된 슬라이드는 블로그 테마를 자동으로 따른다(복사 시 주입). 슬라이드에 별도 작업 불필요" 한 줄 추가
- 앞선 설계 문서(`2026-07-26-slides-embed-design.md`)의 검증 항목 "배포본이 원본과 바이트 동일"은 더 이상 성립하지 않으므로 "주입분 제외 동일"로 정정

## 검증 방법

테스트 러너가 없으므로 산출물과 브라우저로 확인한다.

1. `npm run build` 성공, `out/{글폴더}/slides/index.html`에 주입 블록 존재, 원본에는 없음
2. 브라우저에서 블로그 라이트/다크를 각각 설정하고 글을 열어 임베드 테마 일치 확인
3. 글에서 테마 토글 → 임베드가 즉시 따라 바뀌는지, 표지 스파크라인 색까지 바뀌는지 확인
4. "새 탭에서 열기" → 블로그와 같은 테마로 열리는지 확인
5. 슬라이드에서 `t` 키 → 그 화면만 바뀌고 블로그는 그대로인지, 새로고침하면 블로그 기준으로 돌아오는지 확인
6. 블로그를 `system`으로 두고 OS 테마를 바꿔 양쪽이 함께 따라오는지 확인

## 미확인 지점 / 리스크

- **`storage` 이벤트가 같은 오리진 iframe에 전달되는지 이 조합에서 실측하지 않았다.** 표준상 그렇지만(값을 바꾼 문서만 제외) 확인이 필요하다. 구현 첫 단계에서 브라우저로 검증하고, 전달되지 않으면 차선은 부모 페이지에서 `postMessage`로 알리는 방식이다(양쪽에 코드가 늘고, 새 탭은 어차피 `localStorage`를 읽어야 하므로 경로가 둘로 갈린다)
- next-themes가 테마 변경 시 `localStorage`에 **동기적으로** 쓰는지, 그래서 `storage` 이벤트가 즉시 발생하는지도 같은 단계에서 확인한다
- 주입 문자열이 슬라이드 본문에 우연히 등장할 가능성은 사실상 없지만, 주입 여부는 문자열 검색이 아니라 "이미 주입되었는지" 마커 주석으로 판단한다

## 범위 밖 (YAGNI)

- 슬라이드 테마를 블로그와 **양방향** 동기화 (슬라이드에서 바꾸면 블로그도 바뀌는 것) — 명시적으로 제외했다
- 슬라이드별 테마 고정 옵션 (frontmatter나 파일명으로 강제)
- 라이트 모드 색상 재디자인 — 슬라이드에 이미 완비되어 있다
- `copyFiles`의 mtime 스킵 버그 수정 — 별도 이슈
