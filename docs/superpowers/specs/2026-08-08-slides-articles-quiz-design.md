# 슬라이드 보유 글에 퀴즈 추가 설계

- 작성일: 2026-08-08
- 대상 저장소: `blog-v2.advenoh.pe.kr`

## 1. 목표

슬라이드 데크가 있는 글 중 퀴즈가 없는 5편에 인터랙티브 퀴즈를 추가한다. 퀴즈 인프라(파서·UI·portal)는 이미 구축되어 있으므로 이번 작업은 콘텐츠 작성이다.

## 2. 배경

`/slides` 목록에 오르는 글은 7편이다. 그중 go-fx와 grafana 2편은 이전 작업에서 퀴즈를 갖췄고, 나머지 5편은 없다. 슬라이드가 붙을 만큼 학습 분량이 있는 글이라 퀴즈의 값어치가 크다.

참고로 `contents/` 전체 189편 중 서술형 `<details>` 퀴즈가 남은 글은 **없다**. 이전 작업이 당시 존재하던 퀴즈를 모두 변환했다. 따라서 이번 작업은 변환이 아니라 신규 작성이다.

## 3. 대상

|----|------|------|----------|
| URDF를 이용한 로봇 모델링 | `contents/ros/urdf를-이용한-로봇-모델링/` | 750줄 | 10 |

각 글마다 `index.md`(한국어)와 `index_en.md`(영문) 두 파일을 수정한다. 5편 모두 영문판과 영문 슬라이드를 갖추고 있다.

**문항 수**: 10문항을 목표로 하되, 본문 분량이 감당하지 못하면 8문항까지 줄이는 것을 허용한다. 억지 문항 2개보다 좋은 문항 8개가 낫다. **한국어판과 영문판은 반드시 같은 문항 수·같은 유형 순서·같은 정답 인덱스여야 한다.**

## 4. 삽입 위치와 섹션 번호 재조정

기존 2편의 패턴(`퀴즈 → 마무리 → 참고`)을 따라 **정리/마무리 직전**에 `# N. 퀴즈` 절을 넣고, 뒤 섹션 번호를 한 칸씩 민다.

| 글 | 현재 꼬리 섹션 | 변경 후 |
|----|--------------|---------|
| concurrency-1 | 8.Goroutine Leak / 9.정리 / 10.참고 | 8.Goroutine Leak / **9.퀴즈** / 10.정리 / 11.참고 |
| concurrency-2 | 8.실습 / 9.정리 / 10.FAQ / 11.참고 | 8.실습 / **9.퀴즈** / 10.정리 / 11.FAQ / 12.참고 |
| concurrency-3 | 5.Nil Channel 트릭 / 6.마무리 / 7.참고 | 5.Nil Channel 트릭 / **6.퀴즈** / 7.마무리 / 8.참고 |
| generics-1 | 5.타입 추론 / 6.마무리 / 7.FAQ / 8.참고 | 5.타입 추론 / **6.퀴즈** / 7.마무리 / 8.FAQ / 9.참고 |
| urdf | 6.도구 / 7.FAQ / 8.다음 스터디 주제 / 9.참고 | 6.도구 / **7.퀴즈** / 8.FAQ / 9.다음 스터디 주제 / 10.참고 |

**안전성**: 5편 모두 본문에 섹션 번호 참조(`N장`, `N.N절`)가 **0건**이므로 번호를 밀어도 본문이 깨지지 않는다. 목차는 헤딩에서 자동 생성되므로(`components/article/table-of-contents.tsx`) 별도 작업이 없다. 영문판도 같은 위치·같은 번호로 맞춘다.

## 5. 문항 작성 기준

`CLAUDE.md`의 "퀴즈 (선택)" 절과 이전 작업 리뷰에서 확립된 규칙을 그대로 적용한다.

- 4유형(`mcq`/`ox`/`code`/`blank`)을 섞는다. Go 글은 본문 코드를 `code` 유형에 활용하기 좋다
- **정답 위치를 고르게 분산한다** — 한 인덱스에 쏠리면 같은 버튼만 눌러 만점이 나온다
- **같은 문항의 보기 길이를 비슷하게 맞춘다** — 정답만 설명형으로 길면 길이만으로 티 난다
- `mcq`는 4지선다. 오답은 본문을 대충 읽으면 고를 만한 혼동으로 만들되, **본문 어딘가에서 참인 서술을 오답으로 배치하지 않는다**
- `explain`은 전 유형 필수이고 절 참조를 포함한다. **재조정된 새 번호 기준으로 쓴다**
- **본문에 근거가 있는 것만 묻는다.** 새로운 기술적 사실을 지어내지 않는다
- 형식: 문자열은 큰따옴표, `choices`는 인라인 배열, `code`는 블록 스칼라(`|`)

**도메인 유의**: urdf 글은 ROS/로봇 도메인이라 Go 글들과 성격이 다르다. 본문이 다루는 범위(URDF 태그 구조, link/joint, 도구 사용법) 안에서만 출제한다.

## 6. 작업 단위와 검증

글 1편 = 태스크 1개(한/영 동시)로 5개 태스크. 각 태스크마다:

- **파싱 검증**: `parseQuiz`로 두 파일의 문항 수·유형 순서·정답 인덱스가 서로 일치하는지
- **품질 수치**: mcq 보기 길이 배열과 정답 인덱스 분포 출력
- **섹션 번호**: 헤딩 목록을 출력해 재조정이 표대로 됐는지, 한/영이 같은지
- **브라우저 확인**: `npm run build` + `npx serve out -l 3000` 후 Playwright로 한/영 페이지 렌더·판정 확인

> 이 환경의 `npm run dev`는 동적 slug 라우트에서 500이 난다(Turbopack dev + `output: export`, 기존 문제). 페이지 확인은 반드시 build + serve로 한다.

마지막 태스크에서 전체 빌드와 10개 페이지(5편 × ko/en) 최종 확인.

## 7. 이번 범위에서 제외

- `/quiz` 목록 페이지와 헤더 메뉴 — **다음 작업으로 분리한다.** 콘텐츠 작성과 라우트·manifest 코드 변경은 리뷰 기준이 달라 한 PR에 섞으면 둘 다 얕아진다. 이 작업이 끝나면 대상 글이 7편이 되어 목록 페이지가 채워진 상태로 검증된다
- 퀴즈가 없는 나머지 182편
- 슬라이드 데크(`slides.html`) 수정
- 퀴즈 컴포넌트·파서 코드 수정

## 8. 완료 기준

- 5편 × 2언어 = 10개 파일에 `# N. 퀴즈` 절과 ` ```quiz ` 블록이 있다
- 각 글의 한/영 문항 수·유형 순서·정답 인덱스가 일치한다
- 문항 수는 글마다 8~10이고, mcq 정답 인덱스가 한 값에 쏠리지 않는다
- 섹션 번호 재조정이 4절 표대로 되어 있고 한/영이 같다
- `npm run check`와 `npm run build` 통과
- 10개 페이지에서 퀴즈가 렌더되고 판정·점수가 동작한다 (Playwright 확인)
- `search-index.json`과 `rss.xml`에 퀴즈 YAML이 없다 (기존 필터로 자동 충족되므로 확인만)
